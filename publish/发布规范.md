# 发布规范做法（合规清单）

基于 MIT 项目发布修改版，按下面做即可合规（fork 徽标可选，不影响合法性）：

1. **保留 LICENSE**：仓库根目录保留原 `MIT License` 全文与原版权声明（`Copyright (c) 2026 MyLike`），不要删除或替换成自己的名字。
2. **写 NOTICE**：新增 `NOTICE`，注明「基于 原作者/原仓库 修改」+ 修改点。
3. **README 顶部注明来源**：加一句「本仓库为基于 Hannah2227/MyLike(MIT) 的修改版，详见 NOTICE」。
4. **Release 页面带来源与许可**：用 `publish/RELEASE-v20.md` 作为 Release 说明，正文包含「来源 / 许可证 / 修改说明」。
5. **APK 作为 Release 附件**：安装包挂在 Release 的 Assets，不塞进 git 历史。
6. **版本与标签**：Tag 用 `v20`（或语义化 `1.0.3`），Release 标题写清版本。
7. **不要暗示原作者背书**：不要用原作者名义宣传；不要声称是你原创。
8. **尽量 fork 而非新建**：用 Fork 按钮能自动保留来源关系（徽标）；若新建仓库，务必做到 1~4 项。

可选：在 GitHub 仓库 About 写一句简介并链接原仓库。
